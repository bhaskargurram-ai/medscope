# MedScope

A small open multimodal medical agent that reports what the image actually shows: it localises a finding when it is there, says so when it is not (even after the lesion has been digitally erased), zooms in when it needs a closer look, and asks for a better image when the one it has is unusable.

> **Research use only.** MedScope is not a medical device and must not be used for diagnosis or treatment.

## Running the full pipeline on Colab

Run the notebooks in order. Each one saves to `My Drive/medscope/` and publishes a Google Doc called
"MedScope report - NN ..." with its results. Every long step resumes if Colab disconnects: rerun all cells.

| Notebook | What it does | GPU | Rough time |
| --- | --- | --- | --- |
| `01_build_slake_views` | Download SLAKE, build the four views with LaMa, quality checks | T4 | 30–60 min |
| `02_baselines` | Qwen3.5-4B and MedGemma 1.5 4B zero-shot on the test views | L4 | 2–4 h |
| `02b_natural_negatives` | Unedited images without the lesion: is refusal real or an edit-detection shortcut? Rerun after each training stage | A100/L4 | 20–40 min |
| `03_sft` | Train grounding and agentic LoRA adapters, validation check | L4/A100 | a few hours |
| `04_merge` | Seven ways of merging the two adapters; keep the best | L4 | 2–3 h |
| `05_rl_grpo` | GRPO (plain, then with dynamic sampling) from the agentic adapter | A100 | 4–6 h |
| `07_more_datasets` | Chest X-ray, breast ultrasound and brain MRI: cases, natural negatives, views, checks | T4 or better | ~1 h |
| `08_sft_v2` | Agentic adapter on all five imaging types; says "No" when the lesion is absent | A100 | ~4 h |
| `09_rejection_sampling` | Keep the model's own successful episodes, fine-tune on them, pick the final model | A100 | ~4 h |
| `10_final_eval_export` | Final model, six open baselines and an ablation on the full test set; export | A100, High-RAM | 8–12 h |

Notebooks 01–05 built the first version (CT/MRI and colonoscopy, refer-only); their results are in
`docs/RESULTS_LOG.md`. Notebooks 07–10 build the final model on top of 01's data and 02b's negatives.

## The four views

Every image–question pair becomes four views, each with an expected action:

| View | How it's made | Expected action |
| --- | --- | --- |
| `original` | Unchanged | Answer + evidence box |
| `target_removal` | Lesion inpainted from surrounding tissue | Say it isn't there ("No"); referring is safe but scores less |
| `random_removal` | Same operator on a lesion-free region of the same size | Answer + evidence box |
| `degraded` | Blur, noise, low resolution or a mismatched image | Ask for clarification |

A fifth kind, `natural_negative`, is an unedited image without the lesion, labelled by the dataset. It
gets the same expected reply and the same reward as `target_removal`, so a model gains nothing by
detecting edits. The random-removal view is the control: a model that says "No" on both edited views
is reacting to the editing, not to the lesion. The evidence sensitivity gap (ESG) measures exactly that.

## Output protocol

The model reasons in free text, then emits exactly one tagged JSON object per turn:

```
<tool>{"name": "zoom", "box": [x1, y1, x2, y2]}</tool>
<tool>{"name": "window", "center": 40, "width": 400}</tool>
<final>{"action": "answer", "answer": "left lower lobe", "box": [x1, y1, x2, y2], "confidence": 0.82}</final>
<final>{"action": "clarify", "question": "Is there a lateral view?"}</final>
<final>{"action": "refer", "reason": "No visible evidence of the finding asked about."}</final>
```

Boxes use integer coordinates normalised to 0–1000 on the original full image, including after zooming.

## Quick start

```bash
pip install -e .            # core: numpy, pillow, opencv, pyyaml
python -m unittest -v       # all tests run on CPU

python scripts/prepare_slake.py --root data/raw/slake --out data/cases/slake
python scripts/build_views.py --manifest data/cases/slake/cases_test.jsonl --out data/views/slake_test --inpainter lama
python scripts/check_views.py --views data/views/slake_test/views.jsonl --dedup-against data/views/slake_train/views.jsonl
```

Or open `notebooks/01_build_slake_views.ipynb` in Colab and run all cells.

## Automated quality checks

No human annotation is used anywhere. `check_views.py` keeps a case only if:

- **the lesion is really gone** in the target-removal view: it no longer stands out from the surrounding tissue (a learned detector can be plugged in);
- **the evidence is intact** in the random-removal view: no lesion pixel changed;
- **it is not a duplicate** of a training image (perceptual hash, confirmed by pixel correlation).

Across the whole split it also reports a **shortcut AUC**: how well a classifier tells target-removal edits from random-removal edits by texture alone. It should be at or below 0.6; it needs at least 50 cases to be meaningful. OpenCV Telea inpainting scores about 0.6 on synthetic tests, which is why real builds use LaMa.

Training extras (`pip install -e ".[train]"`) are meant for Colab with a GPU.
